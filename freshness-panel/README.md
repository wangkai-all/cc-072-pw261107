# 数据产品新鲜度面板

面向数仓数据产品的新鲜度监控面板：登记每张表的**预期更新频率、可接受延迟（SLA 承诺）和下游使用方**，
基于本地任务运行记录评估每个产品当前是**按时 / 临近超时 / 已过期 / 计划停更**，
并支持时间回放观察状态随批次到达、失败、补齐而变化的全过程。全部数据为虚构数据，无外部依赖，可离线打开。

## 快速开始

```bash
# 重新生成虚构运行记录（确定性，固定随机种子）
python3 -I tools/generate_data.py

# 运行全部测试（24 个引擎规则测试 + 6 个 DOM 冒烟测试，零依赖）
node --test tests/*.test.mjs

# 本地预览
python3 -I -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765/index.html
```

## 功能与需求对应

| 需求 | 实现位置 |
| --- | --- |
| 登记预期更新频率、可接受延迟、下游使用方 | `tools/generate_data.py` 的 `products`，面板「数据产品登记与当前状态」表 |
| 按时 / 临近超时 / 已过期三态 | `js/engine.js` `evaluateProduct`：deadline = 计划时刻 + 容忍延迟，进入预警窗口为 warning，越过 deadline 为 overdue |
| 点击异常看最近成功批次、缺失分区、受影响报表 | 产品行点击打开详情抽屉（`js/app.js` `openDrawer`），含最近成功批次、缺失/等待分区、运行记录、传递下游消费者与血缘路径 |
| 节假日 / 暂停维护 / 上游延迟使用不同日历，计划停更不误报 | `calendars` 配置（节假日 + 带产品范围的维护窗口），`calendarLookup` 让停更槽位不产生调度义务，状态显示「计划停更」 |
| 迟到批次补齐后状态恢复，异常历史与受影响消费者保留 | 补齐后当前状态恢复 on_time，违约事实进入 `lateRecovered`；`buildIncidentHistory` 永久保留事件生命周期（含 open/recovered、影响消费者） |
| 同一分区重试不重复计算新鲜度 | `buildRunIndex` 以分区为键合并多次 attempt，只取首次成功时间，重试次数单独记录 |
| 调整承诺、查看历史趋势、筛选高影响产品 | 抽屉内 SLA 调整表单（写入承诺变更史并即时重算）；每日状态堆叠柱 + SLA 达成率折线 + 分区健康热力图；顶部筛选行支持状态/层级/等级/关键字/影响分 ≥ 75 |
| 用虚构运行记录演示状态变化 | 顶部回放条：每步 30 分钟，1×/2×/4× 速度，可拖动时间轴；引擎按观测时刻过滤「未来记录」，还原当时真实可见状态 |

## 关键设计决策

1. **观测时刻语义（回放正确性的核心）**：`buildRunIndex(runs, visibleAtMs)` 会忽略晚于观测时刻才结束的批次。
   否则在回放历史时刻时，数据集中“未来才成功”的批次会让产品被错误地显示为按时。
2. **承诺历史按生效时间作用**：`effectiveSchedule` 使 SLA 调整只影响其生效之后的评估，调整前的违约事实仍然成立。
3. **传递血缘**：`buildLineage` 沿表级消费者向下追溯到报表/看板并去重，异常详情展示完整血缘路径（如 ODS → DWD → ADS → 驾驶舱）。
4. **状态色不单独承载含义**：所有状态均为「图标 + 文字 + 颜色」三重编码，并提供图表的表格视图兜底（遵循 dataviz 无障碍规范）。

## 目录结构

```
freshness-panel/
├── index.html              # 面板页面骨架
├── css/styles.css          # 设计令牌（浅/深色）、布局、状态徽章
├── js/
│   ├── engine.js           # 纯函数规则引擎：调度、日历、状态机、事件生命周期、趋势、热力矩阵
│   ├── charts.js           # 轻量 SVG 图表（堆叠柱、折线、热力图）+ tooltip + 表格视图
│   └── app.js              # 回放、筛选、产品表、详情抽屉、承诺调整
├── data/sample-data.js     # 虚构数据（生成产物，globalThis.FRESH_DATA）
├── tools/generate_data.py  # 虚构数据生成器
└── tests/
    ├── engine.test.mjs     # 引擎规则单元/端到端测试
    └── smoke.dom.test.mjs  # 最小 DOM 桩下的应用初始化与交互冒烟测试
```

## 虚构数据覆盖的场景

- `dwd_trade_order_detail`：**当前未恢复的上游断流**（11-13 连续 4 个小时分区缺失，09 点分区运行中），P0 高影响
- `dwd_trade_order_detail` 11-05、`dws_user_act_daily` 11-10、`dwd_click_stream` 11-08：**迟到补齐后恢复**，事件历史保留
- `ads_sales_dashboard` 11-05、`ads_management_dashboard` 11-13：**计划维护窗口内不调度、不误报**
- 2026-11-02 公司盘点假：**节假日全站停更无事件**
- `ods_mysql_orders` 11-12 14 点分区：**失败后重试成功，同分区只计一次新鲜度**
- `ads_finance_monthly`：每月 1 日月结槽位，演示月频调度
